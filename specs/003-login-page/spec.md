## 의존 명세

- [공통 Header 명세](../001-common-header/Header.md)
- `/login`에서는 공통 Header가 접힌 상태로 시작한다.
- 비로그인 사용자의 기본 화면에는 비로그인·접힘 Header를 적용한다.
- 로그인 사용자의 접근 제한 안내 중에는 로그인·접힘 Header를 적용한다.
- Header의 펼침·접힘, 사용자 상태 표시, 로고와 메뉴 동작은 공통 Header 명세를 따른다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 이메일과 비밀번호로 로그인 (우선순위: P1)

비로그인 사용자는 가입한 이메일과 비밀번호를 입력해 본인 계정으로 로그인하고 메인 화면으로 이동한다.

**우선순위 이유**: 기존 계정 사용자가 서비스에 접근하는 가장 기본적인 인증 흐름이다.

**독립 검증**: 비어 있는 로그인 화면에서 유효한 계정 정보를 입력하고 로그인을 완료해 메인 화면과 로그인 상태 Header를 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 로그인 화면에 처음 진입했을 때, **동작** 화면을 확인하면, **결과** 비로그인·접힘 Header, 로고와 소개 문구, 비어 있는 이메일·비밀번호 입력란, 선택되지 않은 자동 로그인, 비활성화된 로그인 버튼과 간편 로그인 버튼이 표시되고 오류와 요청 중 상태는 표시되지 않는다.
2. **상황** 유효한 계정의 이메일과 비밀번호가 입력되어 있을 때, **동작** 사용자가 로그인 버튼을 선택하면, **결과** 이메일 로그인이 한 번 요청된다.
3. **상황** 이메일 로그인이 성공했을 때, **동작** 로그인 상태 갱신이 완료되면, **결과** Header가 로그인 상태로 변경되고 메인 화면(`/`)으로 이동한다.
4. **상황** 이메일 또는 비밀번호가 비어 있거나 이메일 형식이 올바르지 않을 때, **동작** 사용자가 해당 입력란에서 벗어나면, **결과** 입력란 아래에 오류가 표시되고 로그인 버튼은 비활성화된다.
5. **상황** 오류가 표시된 입력값을 사용자가 수정할 때, **동작** 입력값이 유효해지면, **결과** 해당 오류가 해제되고 모든 입력값이 유효할 때 로그인 버튼이 활성화된다.
6. **상황** 이메일 로그인 요청이 시작됐을 때, **동작** 요청이 진행되는 동안, **결과** 화면 전체에 진행 상태가 표시되고 모든 로그인 동작이 비활성화되어 중복 또는 교차 요청이 차단된다.
7. **상황** 이메일 로그인이 실패했을 때, **동작** 실패 결과가 반환되면, **결과** 이메일은 유지되고 비밀번호는 초기화되며 폼 근처에 “이메일 또는 비밀번호를 확인해 주세요.”가 표시된다.
8. **상황** 자동 로그인을 선택하고 이메일 로그인을 완료했을 때, **동작** 로그인 후 서비스를 다시 이용하면, **결과** 최대 30일 또는 그 전에 명시적으로 로그아웃할 때까지 로그인 상태가 유지된다.

### 사용자 스토리 2 - 카카오 또는 구글로 간편 로그인 (우선순위: P2)

비로그인 사용자는 이메일과 비밀번호를 직접 입력하지 않고 카카오 또는 구글 계정을 선택해 로그인한다.

**우선순위 이유**: 외부 계정을 보유한 사용자가 더 적은 입력으로 서비스에 접근할 수 있게 한다.

**독립 검증**: 카카오와 구글 버튼을 각각 선택해 해당 로그인 과정으로 이동하고, 성공 후 메인 화면과 로그인 상태 Header를 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 로그인 화면에 있을 때, **동작** 카카오 로그인 버튼을 선택하면, **결과** 카카오 계정 로그인 과정으로 이동한다.
2. **상황** 비로그인 사용자가 로그인 화면에 있을 때, **동작** 구글 로그인 버튼을 선택하면, **결과** 구글 계정 로그인 과정으로 이동한다.
3. **상황** 카카오 또는 구글 로그인이 성공했을 때, **동작** 서비스로 돌아오면, **결과** 로그인 상태가 갱신되고 메인 화면(`/`)으로 이동한다.
4. **상황** 사용자가 카카오 또는 구글 인증을 취소했을 때, **동작** 서비스로 돌아오면, **결과** 별도 오류 안내 없이 로그인 화면이 표시되고 사용자는 다시 시도할 수 있다.
5. **상황** 카카오 또는 구글 인증이 실패했을 때, **동작** 서비스로 돌아오면, **결과** 로그인 폼 근처에 간편 로그인 실패 안내가 표시되고 사용자는 다시 시도할 수 있다.

---

### 사용자 스토리 3 - 접근 제한과 보조 로그인 경로 (우선순위: P3)

로그인 사용자는 로그인 화면에 중복 접근하지 않으며, 비로그인 사용자는 회원가입 경로를 이용할 수 있다.

**우선순위 이유**: 잘못된 접근을 정리하고 비밀번호 로그인이 어려운 사용자에게 다음 행동을 제공한다.

**독립 검증**: 로그인 상태의 접근 제한과 회원가입 이동을 각각 확인한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 `/login`에 접근했을 때, **동작** 접근 상태가 확인되면, **결과** “이미 로그인하셨습니다. 메인페이지로 이동합니다.” 알림이 표시되고 확인 후 메인 화면(`/`)으로 이동한다.
2. **상황** 비로그인 사용자가 회원가입 안내를 보고 있을 때, **동작** 회원가입 링크를 선택하면, **결과** 회원가입 화면(`/signup`)으로 이동한다.

### 예외 상황

- 이메일이 비어 있거나 이메일 형식이 올바르지 않으면 해당 입력란 아래에 오류를 표시한다.
- 비밀번호가 비어 있으면 해당 입력란 아래에 오류를 표시하며, 로그인에서는 회원가입용 비밀번호 조합 규칙을 다시 검사하지 않는다.
- 이메일과 비밀번호 오류는 사용자가 해당 입력란에서 벗어날 때 표시하고, 이후 입력값이 유효해지는 즉시 해제한다.
- 로그인 버튼은 이메일과 비밀번호의 필수·형식 검증이 모두 통과한 경우에만 활성화한다.
- 이메일 로그인 요청 중에는 화면 전체에 진행 상태를 표시하고 모든 로그인 입력과 버튼 및 인증 동작을 비활성화한다.
- 이메일 로그인이 실패하면 이메일은 유지하고 비밀번호는 초기화한 뒤 로그인 폼 근처에 “이메일 또는 비밀번호를 확인해 주세요.”를 표시한다.
- 로그인 페이지의 비밀번호 입력란은 표시·숨김 기능 없이 항상 마스킹한다.
- 자동 로그인을 선택하면 최대 30일 또는 명시적 로그아웃까지 로그인 상태를 유지하고, 선택하지 않으면 브라우저 종료까지 유지한다.
- 자동 로그인 선택은 이메일 로그인에만 적용하며 카카오·구글 로그인에는 적용하지 않는다.
- 카카오 또는 구글 인증을 취소하면 안내 없이 로그인 화면으로 돌아오고, 실패하면 폼 근처에 실패 안내를 표시하며 두 경우 모두 다시 시도할 수 있다.
- 매직 링크 로그인은 이번 기능 범위에서 제외하며 UI와 동작은 추후 별도 명세에서 결정한다.
- 로그인한 사용자의 접근 제한 알림이 확인되기 전까지는 로그인·접힘 Header를 표시한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 `/login`에서 비로그인 사용자가 로그인할 수 있는 화면을 제공해야 한다.
- **FR-002**: 로그인 사용자가 `/login`에 접근하면 “이미 로그인하셨습니다. 메인페이지로 이동합니다.” 알림을 표시하고 사용자가 확인한 후 메인 화면(`/`)으로 이동시켜야 한다.
- **FR-003**: 로그인 화면은 공통 Header를 접힌 상태로 표시해야 한다.
- **FR-004**: 최초 진입 시 이메일과 비밀번호는 비어 있고 자동 로그인은 선택되지 않으며 입력 오류와 요청 중 상태는 표시되지 않아야 한다.
- **FR-005**: 화면은 큰 로고와 서비스 소개 문구, 이메일 로그인 폼, 카카오·구글 로그인 버튼, 회원가입 안내와 링크를 제공해야 한다.
- **FR-006**: 이메일은 필수이며 올바른 이메일 형식이어야 한다.
- **FR-007**: 비밀번호는 필수이고 기본적으로 마스킹되어야 하며, 로그인 단계에서는 회원가입용 조합 규칙을 검사하지 않아야 한다.
- **FR-008**: 이메일과 비밀번호 입력 오류는 해당 입력란에서 벗어날 때 입력란 아래에 표시하고, 사용자가 값을 수정해 유효해지는 즉시 해제해야 한다.
- **FR-009**: 로그인 버튼은 이메일과 비밀번호의 필수·형식 검증이 모두 통과한 경우에만 활성화해야 한다.
- **FR-010**: 유효하지 않은 입력 상태에서는 로그인 버튼을 비활성화하고 이메일 로그인 요청을 시작하지 않아야 한다.
- **FR-011**: 유효한 이메일과 비밀번호로 로그인 버튼을 선택하면 시스템은 이메일 로그인을 한 번 요청해야 한다.
- **FR-012**: 이메일 로그인 요청은 사용자가 입력한 이메일과 비밀번호를 사용해야 한다.
- **FR-013**: 이메일 로그인 요청 중에는 화면 전체에 진행 상태를 표시하고 모든 로그인 입력, 버튼 및 인증 동작을 비활성화하여 중복 또는 교차 요청을 차단해야 한다.
- **FR-014**: 이메일 로그인이 성공하면 사용자 로그인 상태와 Header를 갱신한 뒤 메인 화면(`/`)으로 이동해야 한다.
- **FR-015**: 이메일 로그인이 실패하면 이메일과 비밀번호 중 어느 값이 잘못됐는지 구분하지 않는 공통 오류를 표시해야 한다.
- **FR-016**: 이메일 로그인 실패 시 이메일 입력값은 유지하고 비밀번호는 초기화한 뒤 로그인 폼 근처에 “이메일 또는 비밀번호를 확인해 주세요.”를 표시해야 한다.
- **FR-017**: 비밀번호 입력란은 표시·숨김 기능을 제공하지 않고 항상 마스킹된 상태를 유지해야 한다.
- **FR-018**: 자동 로그인 선택 항목은 사용자가 로그인 상태 유지 여부를 선택할 수 있게 해야 한다.
- **FR-019**: 이메일 로그인에서 자동 로그인을 선택하면 최대 30일 또는 사용자가 명시적으로 로그아웃할 때까지 로그인 상태를 유지해야 한다.
- **FR-020**: 이메일 로그인에서 자동 로그인을 선택하지 않으면 브라우저가 종료될 때까지 로그인 상태를 유지해야 한다.
- **FR-021**: 카카오 로그인 버튼을 선택하면 카카오 계정 로그인 과정으로 이동해야 한다.
- **FR-022**: 구글 로그인 버튼을 선택하면 구글 계정 로그인 과정으로 이동해야 한다.
- **FR-023**: 카카오 또는 구글 로그인이 성공하면 사용자 로그인 상태와 Header를 갱신한 뒤 메인 화면(`/`)으로 이동해야 한다.
- **FR-024**: 자동 로그인 선택은 이메일 로그인에만 적용하고 카카오·구글 로그인에는 적용하지 않아야 한다.
- **FR-025**: 카카오 또는 구글 로그인을 취소하면 별도 오류 안내 없이 로그인 화면으로 돌아오고 사용자가 다시 시도할 수 있어야 한다.
- **FR-026**: 카카오 또는 구글 로그인이 실패하면 로그인 화면으로 돌아와 폼 근처에 간편 로그인 실패 안내를 표시하고 다시 시도할 수 있어야 한다.
- **FR-027**: 회원가입 안내의 회원가입 링크는 회원가입 화면(`/signup`)으로 연결되어야 한다.
- **FR-028**: 매직 링크 로그인은 이번 기능 범위에 포함하지 않아야 한다.
- **FR-029**: 화면의 배치, 크기, 색상, 타이포그래피와 기본 외형은 연결된 로그인 페이지 디자인을 따라야 하며, 확정된 문구와 동작은 이 명세를 우선해야 한다.
- **FR-030**: 로그인 화면의 Header는 공통 Header 명세를 따라야 한다.
- **FR-031**: 비로그인 사용자의 로그인 화면은 비로그인·접힘 Header를 표시하고 회색 꿀벌 이미지로 사용자 상태를 구분해야 한다.
- **FR-032**: 로그인 사용자의 접근 제한 알림 중에는 로그인·접힘 Header를 표시하고 로그인 상태용 꿀벌 이미지로 사용자 상태를 구분해야 한다.

### 핵심 엔티티 *(데이터를 다루는 경우에만 작성)*

- **로그인 자격 정보**: 사용자가 입력한 이메일과 비밀번호이며 이메일 로그인 요청에 사용된다.
- **자동 로그인 설정**: 이메일 로그인에서만 사용하는 선택값이다. 선택하면 최대 30일 또는 명시적 로그아웃까지, 선택하지 않으면 브라우저 종료까지 로그인 상태를 유지한다.
- **로그인 처리 상태**: 요청 전, 요청 중, 성공, 실패와 실패 안내 상태를 나타낸다.
- **소셜 로그인 제공자**: 카카오 또는 구글 중 사용자가 선택한 외부 계정 로그인 경로다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 유효한 계정 정보를 가진 비로그인 사용자는 로그인 화면 진입 후 2분 이내에 이메일 로그인을 완료할 수 있다.
- **SC-002**: 비어 있거나 형식이 잘못된 입력으로 이메일 로그인 요청이 발생하는 사례가 없어야 한다.
- **SC-003**: 이메일 로그인 성공 시 사용자는 한 번의 로그인 요청으로 메인 화면과 로그인 상태 Header에 도달해야 한다.
- **SC-004**: 잘못된 이메일 또는 비밀번호로 실패한 모든 검증 사례에서 어느 값이 틀렸는지를 노출하지 않는 동일한 실패 안내를 확인할 수 있어야 한다.
- **SC-005**: 카카오와 구글 로그인 성공 시나리오 각각에서 사용자가 메인 화면과 로그인 상태 Header에 도달해야 한다.
- **SC-006**: 로그인 사용자는 `/login` 접근 시 지정된 안내를 확인한 뒤 한 번의 확인으로 메인 화면에 도달해야 한다.
- **SC-007**: 회원가입 링크를 한 번 선택해 회원가입 화면에 도달할 수 있어야 한다.
- **SC-008**: 로그인 요청 중 반복 선택으로 두 건 이상의 이메일 로그인 요청이 발생하는 사례가 없어야 한다.
- **SC-009**: 기준 디자인과 비교했을 때 명세에서 승인한 차이를 제외한 주요 화면 요소가 누락되지 않아야 한다.
- **SC-010**: 비로그인 접근과 로그인 접근 제한 상황 모두에서 올바른 접힘 Header와 사용자 상태 이미지가 표시되어야 한다.
- **SC-011**: 자동 로그인 선택 및 미선택 상태에서 각각 지정된 유지 기간이 적용되고, 자동 로그인 선택이 카카오·구글 로그인에 영향을 주는 사례가 없어야 한다.
- **SC-012**: 카카오·구글 인증 취소 시 오류 없이 로그인 화면으로 돌아오고, 인증 실패 시 폼 근처에 오류가 표시되며 두 경우 모두 다시 시도할 수 있어야 한다.

## 가정

- 이메일과 비밀번호, 카카오, 구글 로그인을 처리하고 로그인 사용자 정보를 제공하는 인증 서비스가 별도 제공된다.
- 인증 및 세션 유지의 구체적인 구현 구조는 이 명세에서 결정하지 않는다.
- 실패 응답은 사용자에게 계정 존재 여부나 어떤 입력값이 잘못됐는지 노출하지 않는 공통 안내로 변환할 수 있다.
- Header의 구체적인 동작과 외형은 공통 Header 명세를 따르며 로그인 페이지 명세와 충돌하면 사용자에게 보고한다.
- 매직 링크 로그인은 후속 명세에서 범위, UI와 완료 안내를 결정한다.
- 모바일 로그인 화면은 별도 명세가 없으므로 이번 기능 범위에 포함하지 않는다.
