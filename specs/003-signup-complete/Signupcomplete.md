# 기능 명세: 회원가입 완료 안내

**기능 브랜치**: `feature/signup-complete`

**작성일**: 2026-08-06

**상태**: 초안

**입력**: 사용자 설명: "`docs/specs/Signupcomplete.md`를 기반으로 한 회원가입 완료 페이지 명세"

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 완료 안내와 로그인 이동 (우선순위: P1)

회원가입을 마친 사용자는 완료 안내를 확인하고 로그인 페이지로 이동해 서비스를 계속 이용한다.

**우선순위 이유**: 회원가입 완료를 명확히 알리고 다음 행동을 제공하는 것이 이 페이지의 핵심 가치다.

**독립 검증**: 완료 상태로 페이지에 진입한 뒤 환영 문구, 완료 안내, 로그인 이동 버튼이 표시되고 버튼 선택 시 로그인 페이지가 열리는지 확인한다.

**인수 시나리오**:

1. **상황** 회원가입 완료 직후 전달되는 완료 상태가 있는 사용자, **동작** `/signup/complete`에 진입, **결과** 환영 문구·마스코트·완료 안내·로그인 이동 버튼이 표시된다.
2. **상황** 완료 안내가 표시된 사용자, **동작** `로그인 하러 가기` 버튼 선택, **결과** `/login`으로 이동한다.

---

### 사용자 스토리 2 - 완료 화면의 시각 안내 (우선순위: P2)

회원가입을 마친 사용자는 일관된 시각 구성과 마스코트 움직임을 통해 가입 완료를 인지한다.

**우선순위 이유**: 완료 메시지를 즉시 인식할 수 있어야 가입 흐름이 자연스럽게 끝난다.

**독립 검증**: 완료 상태로 진입했을 때 그라디언트 배경과 디자인 참조의 구성 요소가 표시되고, 마스코트가 정해진 순서와 시간으로 움직이는지 확인한다.

**인수 시나리오**:

1. **상황** 사용자가 완료 화면에 진입, **동작** 화면이 처음 표시됨, **결과** 마스코트는 0.3초 동안 작은 크기에서 원래 크기로 확대된다.
2. **상황** 확대 애니메이션이 끝난 마스코트, **동작** 화면이 유지됨, **결과** 0.8초 주기로 위아래 12px 이동을 무한 반복한다.
3. **상황** 완료 화면이 표시됨, **동작** 사용자가 화면을 확인, **결과** Figma 가입완료 페이지 프레임의 그라디언트 배경·문구·마스코트·노란색 둥근 로그인 버튼 구성을 확인할 수 있다.

---

### 사용자 스토리 3 - 잘못된 직접 접근 처리 (우선순위: P3)

회원가입 완료 직후 전달되는 완료 상태 없이 페이지에 접근한 사용자는 잘못된 접근임을 안내받고 로그인 페이지로 이동한다.

**우선순위 이유**: 가입 흐름 밖에서 완료 페이지를 보는 상황을 안내하고 사용자가 로그인 흐름으로 돌아가게 한다.

**독립 검증**: 완료 상태 없이 `/signup/complete`에 직접 진입하여 안내 모달과 로그인 페이지 이동을 확인한다.

**인수 시나리오**:

1. **상황** 회원가입 완료 직후 전달되는 완료 상태가 없는 사용자, **동작** `/signup/complete`에 직접 접근, **결과** `잘못된 접근입니다` 모달이 표시된 후 `/login`으로 이동한다.

### 예외 상황

- 완료 상태가 전달되지 않거나 확인할 수 없으면 정상 완료 화면을 노출하지 않고 `잘못된 접근입니다` 모달 후 `/login`으로 이동한다.
- 자동 로그인, 자동 로그인 실패 처리, 로그인 정보 저장 및 세션 스토리지는 이 기능 범위에 포함하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 경로 `/signup/complete`에서 회원가입 완료 화면을 제공해야 한다.
- **FR-002**: 시스템은 회원가입 완료 직후 전달되는 완료 상태가 있는 사용자에게 환영 문구 `프다에 오신 걸 환영해요!`와 완료 안내 문구 `회원가입이 완료되었어요. 지금부터 나만의 학습을 시작해 보세요.`를 표시해야 한다.
- **FR-003**: 시스템은 완료 화면에 `로그인 하러 가기`라는 노란색 둥근 버튼을 제공해야 한다.
- **FR-004**: 시스템은 사용자가 `로그인 하러 가기` 버튼을 선택하면 `/login`으로 이동해야 한다.
- **FR-005**: 시스템은 자동 로그인을 수행하지 않아야 하며, 로그인 정보 또는 완료 상태를 세션 스토리지에 저장하지 않아야 한다.
- **FR-006**: 시스템은 완료 화면이 처음 표시될 때 마스코트를 0.3초 동안 작은 크기에서 원래 크기로 확대해야 한다.
- **FR-007**: 시스템은 확대 후 마스코트를 0.8초 주기로 위아래 12px 이동시키는 동작을 무한 반복해야 한다.
- **FR-008**: 시스템은 회원가입 완료 직후 전달되는 완료 상태가 없는 사용자가 `/signup/complete`에 접근하면 `잘못된 접근입니다` 모달을 표시한 후 `/login`으로 이동해야 한다.
- **FR-009**: 시스템은 이 페이지에서 Header 의존 명세 `docs/specs/Header.md`를 적용해야 하며, 비로그인·접힌 상태로 시작해야 한다.
- **FR-010**: 시스템은 적용 Header에서 미니 로고와 비로그인 사용자 영역 및 사이트 메뉴 아이콘을 표시하고, 미니 로고 선택 시 Header를 펼쳐야 한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 완료 상태가 있는 사용자는 페이지 진입 후 한 번의 선택으로 로그인 페이지에 도달할 수 있다.
- **SC-002**: 완료 상태가 없는 사용자의 직접 접근 100%는 완료 화면 대신 안내 모달과 로그인 페이지 이동으로 처리된다.
- **SC-003**: 완료 화면이 표시될 때 필수 시각 요소 5개(그라디언트 배경, 환영 문구, 마스코트, 완료 안내, 로그인 버튼)가 모두 표시된다.
- **SC-004**: 마스코트는 화면 진입마다 0.3초 확대 후 0.8초 주기의 12px 상하 움직임을 지속한다.

## 의존성 및 디자인 참조

- 원본 요구사항: `docs/specs/Signupcomplete.md`
- Header 의존 명세: `docs/specs/Header.md`
- 적용 Header 상태: 비로그인·접힘 상태, 초기 접힘. Figma 노드 `169:2145`.
- 완료 화면 디자인: Figma 가입완료 페이지 노드 `150:2365`.
- Header의 현재 활성 메뉴 표시, 모바일 Header 동작, 비로그인 이외 사용자 상태는 이 페이지의 검증 범위에 포함하지 않는다.

## 가정

- 회원가입 흐름은 완료 직후 이 페이지가 판별할 수 있는 완료 상태를 전달한다.
- 직접 접근 안내 모달은 `잘못된 접근입니다` 문구를 표시한 뒤 사용자에게 로그인 페이지를 제공하는 데 필요한 시간만 유지된다.
- 일반 Header 동작 중 현재 페이지에 필요한 비로그인·접힘 상태와 미니 로고 펼치기 동작만 검증한다.
