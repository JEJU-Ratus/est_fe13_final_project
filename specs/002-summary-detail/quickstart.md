# 빠른 시작 및 검증 안내: 요약 및 학습노트 상세

## 목적

요약 및 학습노트 상세의 네 경로, 권한, 잠금, CRUD, 북마크와 퀴즈 흐름이 [기능 명세](./spec.md), [데이터 모델](./data-model.md), [인터페이스 계약](./contracts/summary-detail-contract.md)을 충족하는지 검증한다.

## 사전 조건

- Node.js와 npm이 설치되어 있다.
- 프로젝트 의존성이 설치되어 있다.
- 인터페이스 계약의 실제 서비스가 연결되어 있다.
- 다음 검증 데이터 또는 같은 결과를 제공하는 격리 환경이 준비되어 있다.
  - 공개 요약본: 학습노트가 있는 상태와 없는 상태
  - 잠긴 요약본: 올바른 비밀번호와 잘못된 비밀번호
  - 로그인 사용자 소유 요약본 및 학습노트
  - 다른 사용자가 소유한 학습노트
  - 저장 퀴즈가 있는 학습노트와 없는 학습노트
  - 존재하지 않는 `summaryId`, `noteId`

실제 인증·데이터 서비스가 준비되지 않았다면 제품 경로 구현을 임의 데이터 구조로 완료 처리하지 않는다.

## 실행

```bash
npm run dev
```

브라우저에서 서비스가 출력한 로컬 주소를 열고 아래 시나리오를 수행한다.

## 시나리오 1: 공개 요약본과 목록

1. 학습노트가 있는 `/summary/{summaryId}`에 접근한다.
2. 생성 주제와 AI 요약, 최신 작성순 목록을 확인한다.
3. 각 행에 퀴즈 상태, 작성자, 주제, 작성일이 있고 백분율은 없는지 확인한다.
4. 행을 한 번 선택해 `/summary/{summaryId}/notes/{noteId}`에 도달한다.
5. `더보기`가 `/allnote`로 이동하는지 확인한다.

**예상 결과**: 주요 내용이 3초 이내 표시되고 정렬·표시·이동이 계약과 일치한다.

## 시나리오 2: 빈 목록

1. 학습노트가 없는 공개 요약본에 접근한다.
2. 빈 목록 안내 상태를 확인한다.

**예상 결과**: 목록 행 대신 디자인의 빈 상태가 표시되며 별도 공통 컴포넌트 오류는 발생하지 않는다.

## 시나리오 3: 잠긴 요약본 네 경로

다음 네 경로를 인증 전 각각 직접 연다.

```text
/summary/{summaryId}
/summary/{summaryId}/notes/new
/summary/{summaryId}/notes/{noteId}
/summary/{summaryId}/notes/{noteId}/edit
```

1. 모든 경로에서 보호 콘텐츠보다 먼저 비밀번호 모달이 표시되는지 확인한다.
2. 잘못된 비밀번호를 제출해 `비밀번호가 일치하지 않습니다.`와 재입력을 확인한다.
3. 올바른 비밀번호를 제출하고 콘텐츠를 확인한다.
4. 같은 브라우저 세션에서 나머지 하위 경로를 열어 재인증이 없는지 확인한다.
5. 새 브라우저 세션에서는 다시 인증을 요구하는지 확인한다.
6. 모달을 닫으면 이전 페이지로 이동하는지 확인한다.

**예상 결과**: 인증 전 보호 콘텐츠 노출은 0건이고 원문 비밀번호가 브라우저 영속 저장소에 남지 않는다.

## 시나리오 4: 생성과 수정

1. 로그인 사용자로 `/summary/{summaryId}/notes/new`를 연다.
2. 공백 제목과 51자 제목, 1,001자 본문을 각각 blur·제출해 오류와 요청 차단을 확인한다.
3. 유효한 제목과 선택 본문으로 제출한다.
4. 전체 화면 Loading, 입력·제출 비활성화, 중복 요청 차단을 확인한다.
5. 생성된 상세 경로로 이동하는지 확인한다.
6. 작성자로 수정 경로를 열어 기존 값이 표시되는지 확인한다.
7. 값을 변경해 제출하고 같은 학습노트 상세로 이동하는지 확인한다.
8. 실패 응답에서는 입력값이 유지되고 공통 오류 모달이 표시되는지 확인한다.

**예상 결과**: 유효한 생성·수정 흐름을 2분 이내 완료하고 사용자 행동 한 번당 저장 요청은 하나다.

## 시나리오 5: 접근 권한

1. 비로그인 상태로 작성 URL에 직접 접근한다.
2. 다른 사용자로 수정 URL에 직접 접근한다.
3. 작성자와 비작성자 상태에서 수정·삭제 버튼 노출을 비교한다.

**예상 결과**: 비로그인 작성 접근은 `/login`, 비작성자 수정 접근은 `/allnote`로 이동하며 비작성자에게 수정·삭제 버튼이 표시되지 않는다.

## 시나리오 6: 삭제

1. 요약본 작성자로 삭제 버튼을 선택하고 확인 모달에서 취소한다.
2. 데이터와 현재 페이지가 유지되는지 확인한다.
3. 다시 삭제를 승인하고 Loading과 중복 실행 차단을 확인한다.
4. 요약본과 소속 학습노트가 제거되고 3초 이내 `/allnote`로 이동하는지 확인한다.
5. 학습노트 삭제도 취소·승인 흐름을 반복하고 지정 학습노트만 제거되는지 확인한다.

## 시나리오 7: 북마크와 퀴즈

1. 로그인 사용자로 북마크 아이콘을 선택해 저장 상태가 전환되는지 확인한다.
2. 실패 응답에서 기존 북마크 상태가 유지되고 오류 모달이 표시되는지 확인한다.
3. 저장 퀴즈가 있는 학습노트에서 퀴즈 모달을 연다.
4. 답안 하나를 선택·제출해 정답 또는 오답 결과를 확인하고 모달을 닫는다.
5. 저장 퀴즈가 없는 상태에서 풀 수 없는 안내와 제출 차단을 확인한다.
6. 비로그인 사용자가 퀴즈를 선택하면 로그인 제안 모달이 표시되는지 확인한다.

## 시나리오 8: 찾을 수 없음과 시스템 오류

1. 존재하지 않는 `summaryId`와 `noteId` 경로에 각각 접근한다.
2. 찾을 수 없음 처리를 확인한다.
3. 조회·생성·수정·삭제·북마크·비밀번호 검증에서 시스템 오류를 발생시킨다.

**예상 결과**: 잘못된 식별자는 404로 처리되고 시스템 오류는 정규화된 공통 오류 모달로 표시되며 현재 입력 또는 페이지 상태가 보존된다.

## 정적 검증

```bash
npm run lint
npm run build
```

**통과 기준**:

- 두 명령이 오류 없이 종료된다.
- 명세에 없는 패키지, 데이터 요청 라이브러리, 전역 상태 또는 Supabase 구조가 추가되지 않는다.
- SCSS Module 클래스는 kebab-case이고 JSX에서 대괄호 표기법으로 접근한다.
- 동적 경로의 정적 이동은 `Link`, 결과 기반 이동은 `next/navigation`을 사용한다.
- `"use client"`는 상호작용이 필요한 파일에만 존재한다.
