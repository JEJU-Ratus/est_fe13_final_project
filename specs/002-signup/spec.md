# 기능 명세: 회원가입

**기능 브랜치**: `feature/signup`

**작성일**: 2026-08-05

**상태**: 계획 준비 완료

**입력**: 사용자 설명: "`docs/specs/Signup.md`와 연결된 Figma 디자인 및 사용자 확정 답변을 기준으로 회원가입 기능 명세를 작성한다."

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 회원가입 완료 (우선순위: P1)

비로그인 사용자는 필수 약관에 동의하고 유효한 닉네임, 이메일, 비밀번호를 입력해 계정을 만든다.

**우선순위 이유**: 신규 사용자가 서비스 계정을 생성하는 페이지의 핵심 가치이다.

**독립 검증**: 비어 있는 회원가입 화면에서 모든 필수 항목을 유효하게 입력해 가입을 완료하고 완료 화면에 도달하는지 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 회원가입 화면에 처음 진입했을 때, **동작** 화면을 확인하면,
   **결과** 모든 입력값과 약관 선택이 비어 있고 가입하기 버튼은 비활성화되어 있다.
2. **상황** 모든 필수 약관과 입력값이 유효하고 닉네임·이메일 중복 검사를 통과했을 때, **동작** 가입하기 버튼을 선택하면,
   **결과** 화면 전체에 로딩 상태가 표시되고 회원가입 요청이 한 번 전송된다.
3. **상황** 회원가입 요청이 성공했을 때, **동작** 성공 처리가 완료되면,
   **결과** 회원가입 완료 화면(`/signup/complete`)으로 이동한다.

---

### 사용자 스토리 2 - 입력 및 약관 검증 (우선순위: P2)

사용자는 각 입력란을 벗어날 때 입력 오류와 중복 여부를 확인하고, 문제가 있는 값을 수정해 가입 가능한 상태를 만든다.

**우선순위 이유**: 가입 요청 전에 잘못된 정보와 중복 정보를 발견해 실패 가능성을 줄인다.

**독립 검증**: 약관 선택 상태를 변경하고 각 입력란에 유효하거나 유효하지 않은 값을 입력한 뒤 포커스를 이동해 검증 결과와 버튼 상태를 확인한다.

**인수 시나리오**:

1. **상황** 전체 동의가 해제되어 있을 때, **동작** 사용자가 전체 동의를 선택하면,
   **결과** 두 필수 약관이 모두 선택되고 전체 동의도 선택 상태로 유지된다.
2. **상황** 모든 개별 약관이 선택되어 있을 때, **동작** 하나의 약관을 해제하면,
   **결과** 해당 약관과 전체 동의가 모두 해제 상태가 된다.
3. **상황** 사용자가 필수 입력란에 값을 입력했을 때, **동작** 해당 입력란에서 포커스를 벗어나면,
   **결과** 필수 여부와 형식 조건을 즉시 검증해 오류 문구를 표시하거나 해제한다.
4. **상황** 닉네임 또는 이메일 입력란에서 포커스를 벗어났을 때, **동작** 값의 기본 검증을 통과하면,
   **결과** 중복 여부를 검사하고 사용할 수 없는 값이면 오류를 표시한다.
5. **상황** 모든 필수 조건 중 하나라도 충족하지 않았을 때, **동작** 사용자가 입력이나 약관 상태를 확인하면,
   **결과** 가입하기 버튼은 비활성화되어 있다.

---

### 사용자 스토리 3 - 접근 제한과 실패 복구 (우선순위: P3)

로그인 사용자는 회원가입 화면에 머물지 않으며, 비로그인 사용자는 가입 실패 이유를 이해하고 다시 시도할 수 있다.

**우선순위 이유**: 잘못된 접근을 정리하고 실패 상황에서도 사용자가 다음 행동을 판단할 수 있게 한다.

**독립 검증**: 로그인 상태로 회원가입 화면에 접근하는 경우와 유효한 정보로 가입 요청이 실패하는 경우를 각각 확인한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 `/signup`에 접근했을 때, **동작** 화면 진입이 감지되면,
   **결과** "이미 로그인하셨습니다. 메인페이지로 이동합니다." 안내 Modal을 표시하고 3초 후 메인 화면(`/`)으로 이동한다.
2. **상황** 회원가입 요청이 실패했을 때, **동작** 실패 응답을 받으면,
   **결과** 화면 전체 로딩을 종료하고 실패 원인에 맞게 변환한 사용자용 메시지를 Modal로 표시한다.
3. **상황** 비로그인 사용자가 기존 계정 안내를 보고 있을 때, **동작** 로그인 링크를 선택하면,
   **결과** 로그인 화면(`/login`)으로 이동한다.

### 예외 상황

- 빈 닉네임, 이메일, 비밀번호 또는 비밀번호 확인 입력란에서 포커스를 벗어나면 해당 필수 입력 오류를 표시한다.
- 이메일 형식이 올바르지 않으면 중복 여부와 관계없이 형식 오류를 표시한다.
- 비밀번호가 영문·숫자·특수문자를 모두 포함하지 않거나 8~16자 범위를 벗어나면 오류를 표시한다.
- 비밀번호 확인이 비밀번호와 다르면 불일치 오류를 표시한다.
- 닉네임이나 이메일이 이미 사용 중이면 가입하기 버튼을 활성화하지 않는다.
- 회원가입 요청 중에는 화면 전체 로딩을 표시하고 추가 가입 요청을 차단한다.
- Figma의 선택 항목 안내 문구는 실제 선택 약관이 없으므로 표시하지 않는다.
- Figma에 없는 비밀번호 표시·숨김 기능은 확정 요구사항에 따라 두 비밀번호 입력란 모두에 제공한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 `/signup`에서 비로그인 사용자가 회원가입을 진행할 수 있는 화면을 제공해야 한다.
- **FR-002**: 로그인 사용자가 `/signup`에 접근하면 안내 Modal을 표시하고 3초 후 메인 화면(`/`)으로 이동시켜야 한다.
- **FR-003**: 회원가입 화면은 공통 Header를 접힌 상태로 표시해야 한다.
- **FR-004**: 최초 진입 시 모든 입력값과 약관 선택은 비어 있고 오류 문구와 로딩 상태는 표시되지 않아야 한다.
- **FR-005**: 화면은 회원가입 제목, 구분선, 약관 동의 영역, 회원 정보 입력 영역, 가입하기 버튼, 로그인 안내와 링크를 제공해야 한다.
- **FR-006**: 약관 영역은 전체 동의, 서비스 이용약관 동의, AI 생성 콘텐츠 이용 안내 동의를 제공해야 하며 두 개별 약관은 모두 필수여야 한다.
- **FR-007**: 전체 동의를 선택하거나 해제하면 모든 개별 약관이 동일한 상태로 변경되어야 한다.
- **FR-008**: 모든 개별 약관이 선택되면 전체 동의가 선택되고, 하나라도 해제되면 전체 동의도 해제되어야 한다.
- **FR-009**: 실제 선택 약관이 없으므로 전체 동의 설명에 선택 항목 관련 문구를 표시하지 않아야 한다.
- **FR-010**: 닉네임은 필수이며 입력란에서 포커스를 벗어날 때 빈 값 여부를 검증해야 한다.
- **FR-011**: 닉네임의 기본 검증을 통과하면 입력란에서 포커스를 벗어날 때 중복 여부를 검사해야 한다.
- **FR-012**: 이메일은 필수이며 입력란에서 포커스를 벗어날 때 빈 값과 이메일 형식을 검증해야 한다.
- **FR-013**: 이메일 형식 검증을 통과하면 입력란에서 포커스를 벗어날 때 중복 여부를 검사해야 한다.
- **FR-014**: 비밀번호는 영문, 숫자, 특수문자를 각각 하나 이상 포함한 8~16자여야 한다.
- **FR-015**: 비밀번호와 비밀번호 확인은 기본적으로 마스킹되어야 하며 각 입력란에 독립적인 표시·숨김 기능을 제공해야 한다.
- **FR-016**: 비밀번호 입력란에서 포커스를 벗어날 때 필수 여부와 조합 및 길이 조건을 검증해야 한다.
- **FR-017**: 비밀번호 확인 입력란에서 포커스를 벗어날 때 필수 여부와 비밀번호 일치 여부를 검증해야 한다.
- **FR-018**: 입력 오류는 해당 입력란에서 포커스를 벗어날 때 표시하고, 유효한 값으로 수정한 뒤 다시 포커스를 벗어나면 해제해야 한다.
- **FR-019**: 두 필수 약관, 모든 입력 검증, 닉네임·이메일 중복 검사가 모두 통과한 경우에만 가입하기 버튼을 활성화해야 한다.
- **FR-020**: 활성화된 가입하기 버튼을 선택하면 닉네임, 이메일, 비밀번호를 사용해 회원가입을 요청해야 한다.
- **FR-021**: 회원가입 요청 중에는 화면 전체 로딩을 표시하고 중복 요청을 차단해야 한다.
- **FR-022**: 회원가입이 성공하면 회원가입 완료 화면(`/signup/complete`)으로 이동해야 한다.
- **FR-023**: 회원가입이 실패하면 로딩을 종료하고 실패 원인을 사용자가 이해할 수 있는 문구로 변환해 Modal로 표시해야 한다.
- **FR-024**: 이메일 중복을 포함한 구분 가능한 실패 원인에는 해당 원인을 설명하는 사용자용 메시지를 제공해야 한다.
- **FR-025**: 로그인 안내의 로그인 링크는 로그인 화면(`/login`)으로 연결되어야 한다.
- **FR-026**: 화면의 배치, 크기, 색상, 타이포그래피와 기본 외형은 연결된 Figma 프레임을 따라야 하며 이 명세에서 확정한 문구와 동작 차이는 기능 요구사항을 우선해야 한다.

### 핵심 엔티티 *(데이터를 다루는 경우에만 작성)*

- **회원가입 정보**: 사용자가 입력한 닉네임, 이메일, 비밀번호와 비밀번호 확인 값이다. 비밀번호 확인은 일치 검증에만 사용한다.
- **약관 동의 상태**: 전체 동의와 두 필수 약관의 선택 여부이며 가입 가능 여부를 결정한다.
- **입력 검증 상태**: 각 입력값의 필수·형식·일치·중복 검사 결과와 관련 오류 상태이다.
- **회원가입 처리 상태**: 요청 전, 요청 중, 성공, 실패 상태와 실패 원인을 나타낸다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 유효한 정보를 가진 비로그인 사용자는 회원가입 화면 진입 후 5분 이내에 가입을 완료할 수 있다.
- **SC-002**: 모든 필수 입력과 약관 조건을 충족하지 않은 경우 가입하기 버튼이 활성화되는 사례가 없어야 한다.
- **SC-003**: 닉네임·이메일 중복, 이메일 형식, 비밀번호 조합·길이, 비밀번호 불일치 검증 시나리오가 각각 100% 올바른 결과를 표시해야 한다.
- **SC-004**: 회원가입 요청 중 반복 선택으로 두 건 이상의 가입 요청이 발생하는 사례가 없어야 한다.
- **SC-005**: 회원가입 성공 시 사용자는 한 번의 가입 요청으로 완료 화면에 도달해야 한다.
- **SC-006**: 구분 가능한 가입 실패 시 사용자는 실패 원인을 설명하는 Modal을 확인할 수 있어야 한다.
- **SC-007**: 로그인 사용자는 `/signup` 접근 후 안내를 확인하고 3초 이내의 지정된 대기 후 메인 화면으로 이동해야 한다.
- **SC-008**: 기준 Figma 프레임과 비교했을 때 명세에서 승인한 차이를 제외한 주요 화면 요소가 누락되지 않아야 한다.

## 가정

- 닉네임과 이메일 중복 여부를 확인할 수 있는 회원가입 서비스가 제공된다.
- 실패 응답은 사용자용 메시지로 구분할 수 있는 원인 정보를 제공한다.
- Header의 구체적인 동작과 외형은 별도 공통 Header 명세를 따른다.
- 모바일 회원가입 화면은 별도 명세가 없으므로 이번 기능 범위에 포함하지 않는다.
- 인증과 통신의 구체적인 구현 구조는 이 명세에서 결정하지 않는다.
