# 기능 명세: 메인 페이지

**기능 브랜치**: `feature/speckit`

**작성일**: 2026-08-04

**상태**: 초안

**입력**: 사용자 설명: `docs/specs/context/pages/main-page.md`

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 요약 노트 생성 (우선순위: P1)

로그인한 사용자는 메인 페이지에서 요약할 주제를 입력하고, 필요하면 비밀번호를
설정한 뒤 요약 노트를 생성하여 바로 확인할 수 있다.

**우선순위 이유**: 주제를 요약 노트로 만드는 것이 메인 페이지의 핵심 가치이다.

**독립 검증**: 로그인한 사용자가 주제를 입력하고 생성을 요청했을 때 생성된 요약 상세로
이동하는지 확인한다. 비밀번호 사용 여부를 각각 독립적으로 검증한다.

**인수 시나리오**:

1. **상황** 로그인한 사용자가 유효한 주제를 입력했고 비밀번호를 사용하지 않음,
   **동작** 생성 버튼을 누름, **결과** 비밀번호 정보 없이 요약 생성이 요청되고 성공 시 생성된
   요약 상세 페이지로 이동함
2. **상황** 로그인한 사용자가 비밀번호 사용을 선택함, **동작** 비밀번호를 입력하고
   생성 버튼을 누름, **결과** 비밀번호 사용 여부와 비밀번호가 요청에 포함됨
3. **상황** 비밀번호 사용을 선택한 사용자가 비밀번호를 입력하지 않음, **동작** 생성을
   시도함, **결과** 요청이 전송되지 않고 비밀번호 필수 안내를 확인할 수 있음
4. **상황** 생성 요청이 진행 중임, **동작** 사용자가 페이지를 확인함, **결과** 요청 진행
   모달을 통해 현재 상태를 인지할 수 있고 중복 요청을 보낼 수 없음
5. **상황** 생성 요청이 실패함, **동작** 사용자가 오류 모달을 확인함, **결과** 실패 안내를
   확인하고 재시도하거나 모달을 닫을 수 있음

---

### 사용자 스토리 2 - 비로그인 사용자 안내 (우선순위: P2)

비로그인 사용자는 로그인이 필요한 기능을 시도했을 때 서버 요청 대신 로그인 권장 안내를
받고 로그인 또는 전체 요약 목록으로 이동할 수 있다.

**우선순위 이유**: 생성 요청의 권한을 지키면서 비로그인 사용자에게 다음 행동을 명확히 제공한다.

**독립 검증**: 비로그인 상태에서 생성 버튼과 마이페이지 카드를 각각 선택해 로그인 권장
모달이 열리고 예정되지 않은 요청과 화면 이동이 발생하지 않는지 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 주제를 입력함, **동작** 생성 버튼을 누름, **결과** 생성 요청을
   보내지 않고 로그인 권장 모달을 표시함
2. **상황** 비로그인 사용자가 마이페이지 카드를 선택함, **동작** 해당 카드가 활성화됨,
   **결과** 마이페이지로 이동하지 않고 로그인 권장 모달을 표시함
3. **상황** 로그인 권장 모달이 열려 있음, **동작** 사용자가 로그인, 전체 요약 목록, 닫기 중
   하나를 선택함, **결과** 각각 로그인 페이지, 전체 요약 목록으로 이동하거나 모달이 닫힘

---

### 사용자 스토리 3 - 메인 바로가기 이용 (우선순위: P3)

사용자는 메인 페이지의 배너과 바로가기 카드를 통해 관련 페이지로 이동하거나 준비 중인
기능의 상태를 확인할 수 있다.

**우선순위 이유**: 핵심 생성 흐름 외에 주요 페이지와 예정 기능에 접근하는 보조 탐색 경로를
제공한다.

**독립 검증**: 각 바로가기 카드와 배너를 선택했을 때 정의된 페이지 이동 또는 준비 중
안내가 정확히 수행되는지 개별적으로 확인한다.

**인수 시나리오**:

1. **상황** 사용자가 전체 요약 노트 카드를 봄, **동작** 카드를 선택함, **결과** 전체 요약
   목록으로 이동함
2. **상황** 사용자가 퀴즈 카드를 봄, **동작** 카드를 선택함, **결과** 준비 중 모달이 표시됨
3. **상황** 준비 중 모달이 열려 있음, **동작** 닫기를 선택함, **결과** 모달이 닫힘
4. **상황** 로그인한 사용자가 마이페이지 카드를 선택함, **동작** 해당 카드가 활성화됨,
   **결과** 마이페이지로 이동함
5. **상황** 배너 이동 주소가 확정되어 있음, **동작** 사용자가 배너를 선택함, **결과** 지정된
   광고 페이지로 이동함

### 예외 상황

- 주제가 비어 있으면 생성 요청을 보내지 않고 주제 필수 안내를 표시한다.
- 비밀번호 사용이 해제되면 비밀번호 입력을 비활성화하고 현재 값을 생성 요청에 포함하지 않는다.
- 생성 요청이 실패하면 사용자가 실패를 인지하고 다음 행동을 선택할 수 있어야 한다.
- 배너 이동 주소가 확정되기 전에는 임의의 주소로 이동하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 초기 진입 시 빈 주제, 해제된 비밀번호 사용 선택, 비활성화된
  비밀번호 입력, 닫힌 모달, 요청하지 중이 아닌 상태를 표시해야 한다.
- **FR-002**: 시스템은 사용자가 주제 입력을 변경하면 현재 값을 표시해야 한다.
- **FR-003**: 시스템은 주제의 앞뒤 공백을 제거한 후 필수 여부를 검증해야 하며, 공백만 있는 값과
  200자를 초과한 값은 허용하지 않아야 한다.
- **FR-004**: 시스템은 비밀번호 사용 선택에 따라 비밀번호 입력을 활성화하거나 비활성화해야 한다.
- **FR-005**: 시스템은 비밀번호 사용이 선택된 경우에만 숫자 4자리 비밀번호를 필수로
  검증하고 요청에 포함해야 한다.
- **FR-006**: 시스템은 비밀번호 사용이 해제된 경우 비밀번호 값을 생성 요청에 포함하지
  않아야 한다.
- **FR-007**: 시스템은 로그인한 사용자의 유효한 생성 요청에 주제, 비밀번호 사용 여부,
  조건에 따른 비밀번호를 포함해야 한다.
- **FR-008**: 시스템은 생성 요청 중 로딩 모달로 진행 상태를 알리고 중복 요청을 방지해야 한다.
- **FR-009**: 시스템은 생성 요청 실패 시 실패 메시지와 재시도 및 닫기 행동을 포함한 오류
  모달을 표시해야 한다.
- **FR-010**: 시스템은 생성 성공 시 반환된 요약 식별자에 해당하는 요약 상세 페이지로 이동해야 한다.
- **FR-011**: 시스템은 비로그인 사용자가 생성을 시도하면 생성 요청을 보내지 않고 로그인 권장
  모달을 표시해야 한다.
- **FR-012**: 로그인 권장 모달은 로그인 페이지 이동, 전체 요약 목록 이동, 모달 닫기를 제공해야 한다.
- **FR-013**: 시스템은 전체 요약 노트 카드를 선택하면 전체 요약 목록으로 이동해야 한다.
- **FR-014**: 시스템은 퀴즈 카드를 선택하면 준비 중 모달을 표시하고 닫기 행동을 제공해야 한다.
- **FR-015**: 시스템은 로그인한 사용자가 마이페이지 카드를 선택하면 마이페이지로 이동해야 한다.
- **FR-016**: 시스템은 비로그인 사용자가 마이페이지 카드를 선택하면 로그인 권장 모달을
  표시해야 한다.
- **FR-017**: 시스템은 배너 이동 주소가 제공된 경우 배너 선택 시 해당 광고 페이지로 이동해야
  한다.

### 핵심 엔티티 *(데이터를 다루는 경우에만 작성)*

- **요약 생성 입력**: 사용자가 입력한 주제, 비밀번호 사용 여부, 선택적 비밀번호로 구성된다.
- **요약 노트**: 성공적인 생성 결과로, 사용자가 상세 페이지를 열 수 있는 고유 식별자를 가진다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 로그인한 사용자는 메인 페이지 진입 후 3분 이내에 주제를 입력하고 생성 요청을
  시작할 수 있다.
- **SC-002**: 유효한 생성 요청이 성공한 경우 사용자의 95% 이상이 결과 확인 페이지로 이동함을
  3초 이내에 인지할 수 있다.
- **SC-003**: 주제 누락 또는 필수 비밀번호 누락 시 테스트 케이스의 100%에서 생성 요청이 전송되지
  않고 사용자가 문제 항목을 확인할 수 있다.
- **SC-004**: 비로그인 사용자의 생성 및 마이페이지 접근 시도의 100%에서 보호된 행동이 수행되지
  않고 로그인 권장 안내가 표시된다.
- **SC-005**: 사용자는 바로가기 항목을 한 번 선택하여 대상 페이지 또는 준비 중 안내에 도달할 수
  있다.
- **SC-006**: 요청 진행, 요청 실패, 준비 중, 로그인 필요 상태에서 사용자 테스트 참가자의 90%
  이상이 현재 상태와 가능한 다음 행동을 이해할 수 있다.

## 가정

- 메인 페이지의 Header, 마스코트, 배너, 바로가기 카드의 시각 요구사항은 별도 공통 및 디자인
  명세를 따른다.
- 로그인 여부는 메인 페이지 진입 시 확인할 수 있는 상태로 제공된다.
- 요약 생성 성공 시 상세 페이지를 열 수 있는 요약 식별자가 제공된다.
- 배너 이동 주소는 기능 배포 전에 별도로 확정되며, 확정 전에는 임의 주소를 사용하지 않는다.
- 비로그인 마이페이지 카드 행동은 미정 사항의 반복 표기보다 본문의 구체적인 사용자 행동
  정의인 로그인 권장 모달 표시를 기준으로 한다.
