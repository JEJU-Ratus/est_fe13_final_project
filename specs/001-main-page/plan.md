## 요약

메인 페이지에 주제와 선택적 비밀번호를 입력하는 요약 생성 흐름, 로그인 상태별
모달과 이동, 배너·바로가기 상호작용을 구현한다. 페이지의 입력·모달·요청 상태는
클라이언트에서 관리하되, 인\증 공급자와 요약 생성의 전송 방식은 현재 명세에서 결정하지
않는다. 이 기능은 필요한 논리적 입출력 계약만 정의하고, 구체적인 서버 연결은 별도 명세가
확정된 후 연결한다.

## 기술 배경

**언어/버전**: JavaScript, Node.js 24.15.0 현재 개발 환경

**주요 의존성**: Next.js 16.2.12, React 19.2.4, Sass 1.102.x

**저장소**: 해당 없음. Supabase 저장·인증 구조는 본 계획에서 정의하지 않음

**테스트**: 추가 테스트 도구 없음. ESLint, 프로덕션 build, `quickstart.md`의 수동 인수 시나리오

**대상 플랫폼**: 웹 브라우저

**프로젝트 유형**: Next.js 웹 애플리케이션

**성능 목표**: 중복 생성 요청 0건, 정상 성공 후 반환된 식별자의 상세 페이지로 정확히
이동. 사용자 비율 기반 성공 기준은 실제 사용자 조사 계획이 없으므로 구현 검증에서 제외

**제약 사항**: 주제는 공백 정리 후 1~200자, 보호 비밀번호는 숫자 4자리. 인증·서버
계약, 배너 URL, Header 상세 명세, 프로덕션 자산 경로를 임의로 결정하지 않음

**작업 규모**: `/` 페이지 1개, 페이지 전용 스타일 1개, 명세에 있는 공통 UI 의존성 5개,
요약 생성 연결 경계 1개

### 소스 코드

```text
src/
├── app/
│   ├── page.js              # 메인 페이지 상태·상호작용·조합
│   └── page.module.scss     # 메인 페이지 전용 스타일
├── components/
│   ├── Header.jsx           # 별도 공통 명세의 의존성
│   ├── Banner.jsx           # 배너 표시·선택
│   ├── PreparingModal.jsx   # 퀴즈 준비 중 안내
│   ├── SuggestLoginModal.jsx # 비로그인 안내
│   └── QuickLinkCard.jsx    # 바로가기 카드
└── styles/                         # 기존 공통 토큰 재사용
```

**구조 결정**: 페이지에서만 사용하는 입력 폼, 로딩 모달, 오류 모달은 `page.js`에
두고 `page.module.scss`로 스타일한다. `AGENTS.md`에 이미 정의된 공통 컴포넌트는 공통
명세와 구현이 준비된 경우에만 재사용한다. 현재 파일이 없는 Header와 공통 컴포넌트의 생성은
별도 공통 컴포넌트 범위에서 승인받아야 한다.
